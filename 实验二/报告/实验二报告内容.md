## 三、实验内容（2） 存储过程与触发器

### 3.1 创建添加歌曲的存储过程

编写存储过程 add_song_to_playlist，接收用户编号、歌单编号和歌曲编号三个参数，并使用测试歌单 2001 进行验证。过程先检查歌单和歌曲是否存在、用户是否为歌单创建者，以及歌曲是否已被收录，检查通过后将歌曲添加到歌单末尾。这里的用户编号由调用者传入，演示的是业务检查；后续做应用时，还需要从可信的登录信息中取得用户身份。

```sql
INSERT INTO music.playlist (playlist_id, creator_id, playlist_name, visibility)
VALUES (2001, 1, '实验二测试歌单', 'public');
CREATE OR REPLACE PROCEDURE music.add_song_to_playlist(
    IN p_user_id INTEGER, IN p_playlist_id INTEGER, IN p_song_id INTEGER
)
AS
DECLARE
    v_owner INTEGER;
    v_position INTEGER;
BEGIN
    SELECT creator_id INTO v_owner FROM music.playlist
    WHERE playlist_id = p_playlist_id FOR UPDATE;
    IF NOT FOUND THEN
        RAISE EXCEPTION 'Playlist does not exist';
    END IF;
    IF p_user_id IS NULL OR v_owner <> p_user_id THEN
        RAISE EXCEPTION 'Only the playlist creator may add songs';
    END IF;
    IF NOT EXISTS (SELECT 1 FROM music.song WHERE song_id = p_song_id) THEN
        RAISE EXCEPTION 'Song does not exist';
    END IF;
    IF EXISTS (SELECT 1 FROM music.playlist_song
               WHERE playlist_id = p_playlist_id AND song_id = p_song_id) THEN
        RAISE EXCEPTION 'Song already in playlist';
    END IF;
    SELECT COALESCE(MAX(position_no), 0) + 1 INTO v_position
    FROM music.playlist_song WHERE playlist_id = p_playlist_id;
    INSERT INTO music.playlist_song (playlist_id, song_id, position_no)
    VALUES (p_playlist_id, p_song_id, v_position);
END;
/
```

### 3.3 建立歌单修改审计触发器

接下来建立 playlist_audit 表，保存歌单名称、简介和公开状态的新旧值，并记录执行账号和时间。触发函数只在这些字段实际改变时写入记录。审计表没有设置指向歌单的外键，方便日后删除歌单时仍保留修改历史。

```sql
CREATE TABLE music.playlist_audit (
    audit_id BIGSERIAL PRIMARY KEY,
    playlist_id INTEGER NOT NULL,
    old_name VARCHAR(100), new_name VARCHAR(100),
    old_description VARCHAR(1000), new_description VARCHAR(1000),
    old_visibility VARCHAR(10), new_visibility VARCHAR(10),
    db_user VARCHAR(100) NOT NULL,
    changed_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
-- 审计表不设歌单外键，使删除歌单后仍能保留历史记录。
CREATE OR REPLACE FUNCTION music.audit_playlist_update()
RETURNS TRIGGER AS $$
BEGIN
    IF OLD.playlist_name IS DISTINCT FROM NEW.playlist_name
       OR OLD.description IS DISTINCT FROM NEW.description
       OR OLD.visibility IS DISTINCT FROM NEW.visibility THEN
        INSERT INTO music.playlist_audit
        (playlist_id, old_name, new_name, old_description, new_description,
         old_visibility, new_visibility, db_user)
        VALUES (OLD.playlist_id, OLD.playlist_name, NEW.playlist_name,
                OLD.description, NEW.description, OLD.visibility, NEW.visibility,
                CURRENT_USER);
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
CREATE TRIGGER trg_playlist_update_audit
AFTER UPDATE ON music.playlist
FOR EACH ROW EXECUTE PROCEDURE music.audit_playlist_update();
```

### 4.2 核验恢复数据与功能

备份导入后，我分别查询原库和恢复库，对比业务表清单、记录数、公开视图、收录关系、审计记录以及过程和触发器。随后在恢复库开启事务，调用过程并修改歌单，检查功能是否可用，最后用 ROLLBACK 撤销这轮测试。

WHERE table_schema = 'music' AND table_type = 'BASE TABLE' ORDER BY table_name;

UNION ALL SELECT 'playlist', COUNT(*) FROM music.playlist

UNION ALL SELECT 'song_like', COUNT(*) FROM music.song_like
UNION ALL SELECT 'playlist_favorite', COUNT(*) FROM music.playlist_favorite
UNION ALL SELECT 'playlist_audit', COUNT(*) FROM music.playlist_audit
ORDER BY object_name;
SELECT * FROM music.v_public_playlist ORDER BY playlist_id;
SELECT playlist_id, song_id, position_no FROM music.playlist_song ORDER BY playlist_id, position_no;

BEGIN;

## 五、实验总结

这次实验是在实验一的音乐平台上继续做账号权限、存储过程、触发器和备份恢复。和上次主要建表、写查询相比，这次我更关心的是：换一个账号还能做哪些操作，重复的检查能不能交给数据库，以及数据备份后到底能不能恢复使用。

权限这一部分，实际换账号测试后就比较直观了。music_reader 获得授权后可以查询公开歌单，但不能修改业务表；收回权限后，原来能执行的查询也会被拒绝。不过测试时要先确认自己用的是哪个账号，不然在管理员连接里执行成功，也说明不了只读账号有没有权限。我最初尝试切换身份的语句没有通过语法检查，后来直接用 music_reader 重新连接再测试。创建账号时也遇到了不带密码被拒绝的情况，补上临时随机密码后才成功。

存储过程和触发器则让我看到，有些事情不用每次都手动做。添加歌曲前的检查可以写进过程里，调用时传入参数就行；修改歌单后，触发器会自动记录这次变化。这样后续写应用时，就可以直接使用这些已经写好的操作。不过这次过程和触发器是由 omm 执行的，审计记录里记下的也是这个账号。以后真正接入用户登录，还需要处理好平台用户身份和过程参数的对应关系，并继续细化权限。

备份恢复这一部分，我觉得最需要注意的是，生成了备份文件，还得试着恢复一次才放心。实验开始时，服务器虽然开着，数据库却是 Unavailable，启动并确认状态为 Normal 后才继续备份。我把实验前后的两份备份都保留下来，并恢复到独立数据库检查。除了对比数据，还实际调用了过程、修改歌单来测试触发器，确认恢复后这些功能也能用。最后原库保留了测试歌单 2001、对应的歌曲收录关系和审计记录，实验一原有的歌单和偏好样本没有改动。做完之后，我对“备份完成”的理解也具体了一些：不只是有一个文件，还要知道这个文件恢复后能不能继续用。
